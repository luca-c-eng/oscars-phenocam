# PhenoCam metadata

Each captured image is accompanied by a `.meta` sidecar file.

The `.meta` file is generated by:

```text
/usr/local/lib/phenocam/scripts/meta_build.sh
```

## Purpose

The metadata file documents:

- station and acquisition information;
- the PhenoCam software version/build that produced the image;
- Raspberry Pi temperature and throttling state;
- fixed capture parameters;
- EXIF metadata extracted from the JPEG file.

This makes each image traceable across software versions such as `dev/v1.5.0`, `dev/v1.6.0`, and later releases.

## Sections

Current metadata sections are:

```text
[system]
[phenocam]
[system_health]
[capture_params_fixed]
[exif]
```

---

## `[system]`

Contains station, network and acquisition information.

Example:

```text
[system]
sitename=phenozero2
hostname=phenozero2
timestamp=2026-07-10T10:30:05+02:00
datetime_original="2026-07-10T10:30:05+02:00"
tz=Europe/Rome
utc_offset=+2
network=general
lat=nd
lon=nd
elev=nd
start_date=nd
end_date=nd
nimage=nd
iface=wlan0
ip=192.168.1.45
mac=...
image_file=phenozero2_2026_07_10_103005.jpg
```

### Field meaning

| Field | Meaning |
|---|---|
| `sitename` | Station/site name from `/etc/phenocam/settings.txt` |
| `hostname` | Linux hostname |
| `timestamp` | Metadata generation timestamp in ISO-8601 format |
| `datetime_original` | NetCam-compatible alias of the acquisition timestamp |
| `tz` | Timezone label from settings |
| `utc_offset` | UTC offset from settings |
| `network` | Remote layout/network mode currently selected |
| `lat` | Site latitude, or `nd` if not defined |
| `lon` | Site longitude, or `nd` if not defined |
| `elev` | Site elevation in metres, or `nd` if not defined |
| `start_date` | Site start date, or `nd` if not defined |
| `end_date` | Site end date, or `nd` if not defined |
| `nimage` | Site image index/number, or `nd` if not defined |
| `iface` | Network interface used for metadata, for example `wlan0` or `eth0` |
| `ip` | IPv4 address of the selected interface |
| `mac` | MAC address of the selected interface |
| `image_file` | JPEG filename associated with this `.meta` file |

## `[phenocam]`

Identifies the `oscars-phenocam` software build that produced the image and metadata.

Example:

```text
[phenocam]
software_name=oscars-phenocam
software_version=dev/v1.6.0
software_branch=dev/v1.6.0
software_commit=abc1234
installed_at=2026-07-10T10:12:33+02:00
```

### Field meaning

| Field | Meaning |
|---|---|
| `software_name` | Project/software name |
| `software_version` | Version read from `/usr/local/lib/phenocam/VERSION` |
| `software_branch` | Git branch installed by `install.sh` |
| `software_commit` | Short Git commit hash installed by `install.sh` |
| `installed_at` | Installation timestamp in ISO-8601 format |

The `[phenocam]` section identifies the PhenoCam software release.

This is different from the EXIF field:

```text
Software : rpicam-apps
```

The EXIF `Software` value refers to the Raspberry Pi camera stack. It does **not** identify the `oscars-phenocam` release.

Runtime build information is installed by `install.sh` in:

```text
/usr/local/lib/phenocam/VERSION
/usr/local/lib/phenocam/BUILD_INFO
```

The metadata builder reads these files and writes the `[phenocam]` section into every `.meta` file.

## `[system_health]`

Contains Raspberry Pi runtime health information.

Example:

```text
[system_health]
soc_temp_c=50.5
throttled_hex=0x0
arm_clock_mhz=1000
undervoltage_now=0
arm_freq_capped_now=0
throttled_now=0
soft_temp_limit_now=0
undervoltage_occurred=0
arm_freq_capped_occurred=0
throttled_occurred=0
soft_temp_limit_occurred=0
```

### Field meaning

| Field | Meaning |
|---|---|
| `soc_temp_c` | Raspberry Pi SoC/core temperature in degrees Celsius |
| `throttled_hex` | Raw `vcgencmd get_throttled` bitmask |
| `arm_clock_mhz` | Instantaneous ARM clock frequency in MHz |
| `undervoltage_now` | `1` if undervoltage is currently detected |
| `arm_freq_capped_now` | `1` if ARM frequency is currently capped |
| `throttled_now` | `1` if the system is currently throttled |
| `soft_temp_limit_now` | `1` if the soft temperature limit is currently active |
| `undervoltage_occurred` | `1` if undervoltage occurred since boot |
| `arm_freq_capped_occurred` | `1` if ARM frequency capping occurred since boot |
| `throttled_occurred` | `1` if throttling occurred since boot |
| `soft_temp_limit_occurred` | `1` if the soft temperature limit occurred since boot |

The ideal value is:

```text
throttled_hex=0x0
```

This means no current or historical undervoltage, throttling, frequency capping, or soft temperature limit flags since boot.

### Temperature interpretation

| SoC temperature | Interpretation |
|---:|---|
| `< 60 °C` | Normal |
| `60–70 °C` | Warm but generally acceptable |
| `70–80 °C` | Monitor |
| `80–85 °C` | ARM throttling may occur |
| `>= 85 °C` | Higher throttling risk |

These values do **not** represent ambient air temperature. They represent internal Raspberry Pi runtime health.

To measure true environmental temperature, add an external sensor such as DS18B20, BME280, SHT31, or similar.

## `[capture_params_fixed]`

Contains the fixed camera parameters used by the capture script.

Example:

```text
[capture_params_fixed]
width=4608
height=2592
awb=daylight
gain=1.0
sharpness=1.0
contrast=1.0
brightness=0
saturation=1.0
denoise=off
ev=0
lens_position=0.0
quality=100
```

### Field meaning

| Field | Meaning |
|---|---|
| `width` | JPEG capture width in pixels |
| `height` | JPEG capture height in pixels |
| `awb` | White balance mode |
| `gain` | Analogue gain |
| `sharpness` | Image sharpness setting |
| `contrast` | Image contrast setting |
| `brightness` | Image brightness setting |
| `saturation` | Image saturation setting |
| `denoise` | Denoise setting |
| `ev` | Exposure value compensation |
| `lens_position` | Manual lens position |
| `quality` | JPEG quality |

---

## `[exif]`

Contains EXIF metadata extracted from the captured JPEG by `exiftool`.

This section may include camera-stack information such as:

```text
Software : rpicam-apps
```

Again, this is not the PhenoCam software version. The PhenoCam release is recorded in the `[phenocam]` section.

## Manual checks

### Check installed PhenoCam build

```bash
cat /usr/local/lib/phenocam/VERSION
cat /usr/local/lib/phenocam/BUILD_INFO
```

### Check system health

```bash
sudo /usr/local/lib/phenocam/bin/diag_system_health.sh
```

### Inspect `[phenocam]` metadata in queued files

```bash
sudo find /run/phenocam /var/lib/phenocam \
  -type f -name "*.meta" \
  -exec sed -n '/^\[phenocam\]/,/^\[/p' {} \;
```

### Inspect `[system_health]` metadata in queued files

```bash
sudo find /run/phenocam /var/lib/phenocam \
  -type f -name "*.meta" \
  -exec sed -n '/^\[system_health\]/,/^\[/p' {} \;
```

## Version notes

### `dev/v1.5.0`

Introduced:

```text
[system_health]
```

for Raspberry Pi SoC temperature and throttling/undervoltage diagnostics.

### `dev/v1.6.0`

Introduced:

```text
[phenocam]
```

for PhenoCam software version/build traceability.

Also introduced the startup test cycle after boot:

```text
phenocam-startup-cycle.timer
phenocam-startup-cycle.service
phenocam-startup-cycle.sh
```

This restores the expected boot behaviour:

```text
boot
↓
startup test cycle: capture + upload
↓
regular capture/upload cycles by timer
```
